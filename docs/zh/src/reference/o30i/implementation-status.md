# O30i 实现状态与测试范围

本文以 O30i 实际存在的 20 个关节为唯一公开关节模型。固件的运行时对象仍保留 36 个协议槽位，SDK 会负责在 20 个真实关节与 36 个线上槽位之间转换。

## 实际关节定义

| 1 | `yaw_0` | 拇指横摆 | 5 | 0～255 | 50 | 横滚 |
| 2 | `yaw_1` | 食指侧摆 | 6 | 0～255 | 50 | 侧摆 |
| 3 | `yaw_2` | 中指侧摆 | 7 | 0～255 | 50 | 侧摆 |
| 4 | `yaw_3` | 无名指侧摆 | 8 | 0～255 | 50 | 侧摆 |
| 5 | `yaw_4` | 小指侧摆 | 9 | 0～255 | 50 | 侧摆 |
| 6 | `root1_0` | 拇指根 1 | 10 | 0～255 | 128 | 指根 1 |
| 7 | `root1_1` | 食指根 1 | 11 | 0～255 | 128 | 指根 1 |

## 已实现

| 功能 | API | 状态 |
| --- | --- | --- |
| CAN FD 连接与生命周期 | `O30i(...)`、`close()`、上下文管理器 | 已实现；支持厂商动态库与 SocketCAN |
| 关节元数据与默认值 | `O30I_JOINT_SPECS`、`O30I_DEFAULT_RAW_VALUES` | 已实现；固定为上表 20 个关节 |
| 8 位位置读写 | `hand.angle` | 已实现；百分比、原始值、目标值、切片及稀疏写 |
| 16 位位置读取 | `hand.angle.get_i16_blocking()` | 已实现；读取完整 72B 后返回 20 个真实关节 |
| 速度读写 | `hand.speed` | 已实现；20 个原始字节值 |
| 加速度读写 | `hand.acceleration` | 已实现；20 个原始字节值 |
| 转矩读写 | `hand.torque` | 已实现；20 个原始字节值 |
| 运动时间读写 | `hand.motion_time` | 已实现；20 个值，单位 10 ms/tick |
| 电流读取 | `hand.current` | 已实现；只读，返回 20 个值 |
| 电压读取 | `hand.voltage` | 已实现；只读，返回 20 个值 |
| 温度读取 | `hand.temperature` | 已实现；只读，返回 20 个值 |
| 故障读取 | `hand.fault` | 已实现；保留原始故障字节，不猜测未确认 bit 含义 |
| 产品与版本信息 | `hand.version` | 已实现；支持 225B 多帧响应重组 |
| 传感器能力信息 | `hand.sensor` | 已实现；读取 `MI=0x31` 描述信息 |
| 通信错误历史 | `hand.diagnostics` | 已实现；读取 `MI=0x4F` |
| 快照、主机轮询、事件流 | `get_snapshot()`、`start_polling()`、`stream()` | 已实现；覆盖全部高层运行时读取对象 |
| HOP 原始对象访问 | `hand.protocol` | 已实现；供未封装对象的受控调试使用 |

完整的 20 关节写入会被拆为三个 HOP 写请求：`SI=0, EDL=1`、`SI=5, EDL=10`、`SI=16, EDL=9`。这样不会覆盖不存在的关节，但三个请求不是原子事务；若中途发生通信错误，设备可能只接受前面的片段。

## 未实现或不开放

| 功能 / MI | 状态 | 原因 |
| --- | --- | --- |
| 关节映射 `0x00` | 未封装 | 当前固件映射表读取无可靠响应，写回报错 |
| 堵转时间/阈值/维持电流 `0x09～0x0B` | 无高层 API | 通信曾通过，但物理语义与安全范围尚未确认 |
| 有效关节/使能掩码 `0x0C` | 未封装 | 写后读回不生效，不能作为真实使能状态 |
| 位置 16 位局部写 | 未实现 | 当前只确认完整 72B 读取可靠 |
| PID `0x21～0x26` | 未封装 | 固件对象长度与旧协议文档不一致 |
| 触觉数据 `0x32～0x34` | 未实现 | 当前设备报告 `NO_SENSOR` 且数据总长度为 0 |
| 配置 `0x35` | 未封装 | 部分连续字段写失败，缺少稳定写入白名单 |
| 预设动作 `0x36～0x3A` | 未封装 | 触发语义和安全边界未完成验证 |
| 工程服务 `0x42` | 禁止高层写入 | 可能触发 Bootloader、升级或恢复出厂 |
| 单位与量程 `0x43` | 无强类型 API | 可通过 `hand.protocol` 读取，字段语义仍需确认 |
| 设备端主动周期上报 | 未实现 | 当前使用主机主动轮询，未确认固件端配置模型 |

“未封装”不表示可以直接安全写入。除只读诊断外，使用 `hand.protocol` 访问这些对象前必须先确认当前固件版本、字段范围和失效行为。

## 自动化测试

O30i 测试位于 `tests/hand/o30i/`，底层 HOP 测试位于 `tests/hand/hand_protocol_v1/`。当前自动化测试覆盖：

- 20 个关节的 ID、中文名、默认值、分组和线上槽位；
- 36 槽读取到 20 关节的投影，以及 8 位/16 位解码；
- 三段批量写、跨空槽切片、稀疏关节编号和所有写入 manager；
- 长度、类型、范围、空切片、越界和截断响应校验；
- 产品信息多帧重组、传感器能力、诊断错误对象；
- 生命周期、两种 CAN FD 后端参数、快照、轮询和事件流；
- HOP 帧编解码、错误响应、超时、分片和串行请求。

运行命令：

```bash
uv run pytest tests/hand/o30i tests/hand/hand_protocol_v1
```

这些测试使用模拟 dispatcher，不会驱动真实电机。真实硬件仍需在限速、卸载和可急停条件下验证运动方向、默认姿态、单位及各固件版本兼容性。
